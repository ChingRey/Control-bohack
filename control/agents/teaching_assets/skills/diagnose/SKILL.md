# 诊断与安排教学

适用：开始教学、源码变更、学生卡住或目标完成。

1. 查看学生原始需求、当前代码、已给提示与作答；不凭一条消息推断能力高低。
2. 区分未表达清楚、缺知识、推理错误、操作未验证。证据不足先问。
3. 选择与当前开发有关的一个目标，写明选择依据和可观察的成功表现。
4. 自主选教学动作，不要求学生重复已经证明会的内容。发现先备知识缺口可补讲后再回来。
5. 连续无进展要换方法；学生要求暂停时总结并保留未解决项。

输出：本轮目标、简短理由、下一步动作、待处理问题。

项目教学从目标和计划草稿开始，确认前不切到代码纠错。开发后把当前源码当教材，先解释实际实现与数据流，需要时补充技术基础，再讨论错误。技术扩展由学生选择，现在不学也不阻止继续开发；补讲后接回原问题。

依据：CMU 强调了解学生已有知识，并使目标、活动与评价一致。
