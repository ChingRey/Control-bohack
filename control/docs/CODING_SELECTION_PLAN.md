# Control Coding Agent 选型方案

日期：2026-11-13。状态：文档核查后的实施建议，未完成真实模型验证。

## 决策

首选 OpenCode + 阿里云百炼 qwen3-coder-flash API。框架版本及服务端接口须在隔离实验中锁定；不能混用 OpenCode V1 的 serve/SDK 与新版配置。第一轮用按量 API，不默认使用面向特定工具的订阅额度。模型权限、地区、具体快照和价格以账户控制台及条款核实结果为准。

Flash 是可用性候选，不预判它一定弱或一定有教学价值。对照 qwen3-coder-plus，主要检验 Flash 能否交付中小项目又有局部、可教学的自然失败。Plus 只作为上限对照，不能把更换 Plus 称为学习。如果 Flash 已过强，另选 API 可用且支持可靠工具调用的更小模型；不通过诱导错误、隐藏测试结果或极低预算制造弱点。

不优先 Qwen2.5-Coder-7B/14B：本轮已确定用户 API 路线，其可购买的固定部署与 OpenCode 工具兼容性尚未核实，不能因权重可下载就假定能直接购买对应 API。豆包 Code 为第二服务商候选；先核验确切模型 ID、工具调用、地区和价格，不以泛称“豆包”接入。

## 结构与实施调整

Control Python 后端保持入口；新增 OpenCodeCodingAgent，兼容 step(task,instruction,learning_context=None)。OpenCode 作为受控本地子进程/服务执行，用户模型 API Key 只从进程内传入，禁用凭据持久化路径并实测；不得调用默认登录命令后宣称密钥仍仅在内存。

每个任务独立工作目录、配置与会话。只执行学生已确认当前一步，允许步内多次读写和验证；轮次结束后不提交下一步。紧急停止需支持终止执行并记录部分改动，不能承诺中断等于自动回滚。项目外访问、网络、依赖安装和 shell 依靠受限执行环境及权限处理，工作目录本身不是沙箱。

现有同步 sample 接口不能直接承载长模型执行：新增 coding_run 后台状态，保留 expected_step 与任务锁语义。不要在长期模型调用中持有数据库事务；对源码哈希和步骤做乐观校验，避免覆盖学生编辑。完成后记录实际 before/after、工具事件、命令退出码、stdout/stderr 和未验证事项；禁止将模型自述当运行证据。失败不静默切 sample，不自增成功步骤。

第一阶段只在 scripts 独立项目实验，不接前端。第二阶段接三个网页文件，复用 changes 和独立来源预览。多文件中小项目阶段再扩展白名单、文件树、预览与 Teaching 读取范围，不能假定当前三文件限制已支持通用项目。新增构建预览需单独限制服务目录及来源。

## 能力配置

基础配置始终保留诚实报告、路径权限、基本运行验证；不要求随机犯错。固定模型、正常调用预算、禁用自动子代理及强模型路由，初始不加载增强 Skill。不能用被剥夺必要权限造成的失败充当能力缺陷。

小进步：Teaching 从学生原话、代码与验证提出经验草稿，检查依据与范围，通过后进入版本化经验库；相关任务最多加载少量规则，记录 ID、版本、来源与实际请求内容哈希。允许新增非预设问题类别。错误或不适用经验可停用和纠正。

大进步：Teaching 是升级决策者；程序执行不可绕过的两道门槛：学生独立/迁移证据合格，且具体 Skill 已在当前模型/框架组合验证有效。白名单内可自动升级；用户可暂停自动升级和撤回。Coding 不可写能力配置，也不能自行安装 Skill。Teaching 的升级权不包含学生的项目执行确认权。

仅在下一轮开始应用能力版本，进行中的轮次不热换。停用后用新会话和明确项目状态恢复，避免旧会话继续保留 Skill 正文；停用能力不自动撤销已经产生的代码。

先评估 verification-before-completion，再 systematic-debugging，最后 brainstorming/任务拆解。锁定上游 commit、正文哈希及依赖；如删改则作为新变体重新评估。全量安装 Superpowers 会同时改变多项流程，不适合作为首个归因实验。

## 首轮验收

项目 A：多文件浏览器小游戏，含菜单、计分、暂停、重开、持久化；项目 B：带筛选、编辑、持久化的网页工具。先各跑 3 个全新会话基线，每次相同模型/权限/预算，保存所有失败及原始工具轨迹。验收使用独立行为测试，Agent 不可修改验收测试。记录项目可启动、主要功能通过率、回归、虚假完成、成本、人工介入和可教学问题比例。

暂定筛选线（产品假设，不是科研标准）：6 次至少 4 次在预算内交付主要功能；严重越权或伪造结果不能通过。若全过且缺少教学空间，增加需求变更与状态边界后再判断；若仍无区分度则更换候选。少量试验只能筛选，不能证明稳定性。

再对同一模型做单 Skill 启停配对试验，每条件至少 5 次；等预算、随机交错顺序、新会话、相同起点，增加等长度提示控制。冻结经验/Skill 后用未见任务验证迁移并跑旧回归；报告每任务原始计数，不只报汇总提升。调试 Skill 的测试集需提供统一的已知问题起点，明确为调试任务，不能冒充模型自然失败。负收益则撤回，不改 catalog 为 verified。
