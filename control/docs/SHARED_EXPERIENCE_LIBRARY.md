# 可视化经验库：当前单用户、跨项目闭环

2026-11-15。当前需求优先于旧“跨项目需手动复制”“反思仅候选”文档。原实验后端保留兼容，顶部入口已换为本经验库，不再加载旧独立前测/后测试验界面。

## 运行链路

1. 两侧学生消息先保存；Teaching每轮从SQLite experience_library单例取得当前策略版本，匹配最近学生话语和当前计划，最多两条、最多一条试用。关闭模式不注入。
2. Teacher完成且有后续学生表现、至少两条新学生消息，触发原独立后台反思；也可在经验库手动“分析当前项目的新证据”。不强制每次代码执行都改经验，没有有效证据可以不变更。
3. 采集带编号原话、近期代码改动前后片段、学生行为验证、工具测试、浏览器记录、当前计划和代码哈希。作品证据标明是否仍对应当前版本；片段/大记录裁剪明确标记。凭据脱敏后进入快照。不是鼠标点击、字数、停留时长直接算理解。
4. 评价器与反思器均为配置的Teaching模型、不同提示词的两次调用。评价器对固定条目语义判断并引用证据；程序验证引用、角色、时序、分值、证据ID，计算维度分；反思器随后接收已验证评价与原话、提出最多两条增量，并指定dimension_ids及理由。
5. 程序校验增量，BEGIN IMMEDIATE事务内校验共享经验版本，写入来源项目、评分、证据快照、前后对照和新版本。反思支持新增、修改、停用或保持不变：修改保留同一条目ID、归档旧内容并递增版本，重新标为trial、verified=false；停用允许针对预设经验，从后续检索移出但保留历史。每轮最多一条匹配的试用进入教学。旧项目独有条目只初始化迁入一次，不改原始聊天或把旧评分冒充新评分。
6. 后续项目自动读取同一份库，不再复制个人教法。停用和撤销会改变后续输入；Teacher加载记录关联具体项目/回复/内容版本，加载不等于实际采用或证明有效。

## 六维评分设计 v2

每维两个固定条目：理解效果（解释、预测）；难度适配（前置、帮助强度）；信息量与节奏（重点、接续）；项目相关性（目标、作品一致）；独立应用（自主方案、自主验证）；反馈调整（回应困难、调整后表现）。完整锚点在agents/experience_evidence.py，评分输入保留rubric_snapshot/hash，界面可展开。

每项仅0/0.5/1/null。维度分=100×非null条目分之和÷非null条目数；全部null显示证据不足，不生成总分。条目不是独立学生样本，分数只是模型观察、未校准的工程量表。

有分数须引用本批真实原话，学生必需维度还须含学生原话，且有新消息引用。项目作品一致项还必须引用改动/行为/测试/浏览器证据，满分要求匹配当前版本。测试通过、AI代码正确不能代替学生独立理解。没有表现机会就记null。使用记录+后续学生原话才能评价某条教法；不能由单一分数自动推导原因。

## 查看与回退

顶部及首页“经验库”：默认显示全部经验的紧凑矩阵（桌面三列、窄屏两列），条目默认收起，仅显示名称和加入/修改的来源仓库；最近新增或修改的在前，初始教法在后。来源按批次的project_id关联当前仓库名，仓库重命名后自动同步标签，不重写历史证据和当时的名称快照。系统预设单独标记“系统预设 · 加入”，不伪造任务来源；内部版本仍用于排序、并发和回退。顶部仅保留“本轮经验变更”高亮开关及关闭图标；默认用浅红色突出最近有条目变化的一批，再点取消高亮，不过滤条目。没有新条目的评价不冒充经验变更。展开卡片可看来源、适用/动作/预期/边界、评分证据、变更前后、撤销、教学引用与后续反馈；轮询保留展开状态，重新打开全部收起。

新建真实项目先显示可选仓库名称输入；留空由服务端事务分配“未命名仓库一、二……”（各有完整前缀），计数持久保存、跳过已有同名且重命名不释放序号。自定义/默认名称均为manual，后续聊天不自动覆盖，首页可重命名。既有auto项目保留兼容，不批量改名或删除历史。

撤销此项、撤销本轮全部变更；新增条目撤销后停用，不删除审计。expected_revision保护共享库；条目发生后续变更时拒绝覆盖。整库历史恢复保留评价、原话和处理游标，恢复后observe/auto=false，避免立即被自动反思再改回。旧教学已发生的内容不会被回退。

GET /api/experience-library 返回共享库、各项目反思运行状态和加载记录。POST同路径：options/status/restore/undo，必须expected_revision；undo带batch_id，可选entry_id。旧项目experience-manage代理至同一共享库，experience-import明确提示无需复制。

## 实现与验证边界

存储模块experience_library.py、证据与量表experience_evidence.py、原有反思teaching_evolution.py、可视化frontend/evolution.js。无新依赖，不训练权重，不引入跨用户体系。

自动测试覆盖原话伪造/学生角色/新证据、固定公式、作品证据与版本、新经验进入下一项目真实Teacher上下文构建、同ID修改及撤销、预设经验停用、保持不变、并发版本冲突及异步评价→反思→入库。真实Chromium+本机HTTP临时库验证按钮、分数证据、前后对照、跨项目加载和撤销，使用模型夹具，仅证明链路接通。

真实模型隔离演示另存data/demos：已生成使用预设经验和不参考经验的两条教学回复，但单次对照不能证明教学改善；评价调用出现过格式不符、超时和输出达到长度上限，均未提交经验变化。评价使用固定六维十二条目JSON模板，结构错误最多修复一次，与原调用共享后台时间预算，输出上限6000 token；仍须通过原话与证据校验。独立模型评价对照回复也未取得有效JSON，不计为成功验收。

Reflexion与ACE启发反馈反思和增量手册，不保证每次修改单调提升。真正效果需要后续同类任务/学生表现对比；helpful/harmful/uncertain及六维评分均不是因果证明。

## 待验证经验优先（2026-11-15）

新教法仍为trial、verified=false，界面标待验证。场景词匹配是前置条件；匹配池内尚未提供的新经验优先，其次参考匹配数、提供次数和既有观察，每轮至多一个trial。每轮validation_focus带具体教法假设、适用条件、观察目标与边界；同时写入教学轮次和load轨迹。

跨项目汇总同一条目内容版本的加载与反馈：pending（待验证）、awaiting_evidence（已提供，待确认采用与后续表现）、positive_observation/negative_observation（已有模型观察）、inconclusive（不能判断）。加载不等于实际尝试，正向反馈不自动晋升validated；无后续学生证据不凭空结论。不同项目的消息ID始终与project_id关联，内容版本不混算。
