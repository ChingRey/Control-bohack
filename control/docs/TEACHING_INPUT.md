# Teacher 精简输入与接续记忆

本次只替换真实 OpenCode 项目的 Teacher 上下文组装，不删除或更名任何 HTTP 接口。旧 sample 的课程、历史摘要机制保留。

## 输入

- 普通聊天：当前问题原文、最初需求的有界片段、最近4条去重对话、最新计划/执行/验收状态、接续记忆、文件索引。默认不预载源码或检查点。
- checkpoint/review：在上述基础上增加检查点标识、实际变更的文件元数据、删除行、运行/测试记录；预载diff行号附近约10行当前源码，总预算6500个JSON字符。
- 不再重复发送完整diff、源码前120行、计划草稿、检查点中的Coding完成说明、多份进度字段。新建文件同样受源码预算约束；未提供不等于不存在，完整内容可按需只读补查。
- 当前学生问题不截断；其他聊天有截断标记、原始消息编号。完整聊天、diff、源文件、历史记录继续保留。

## 接续记忆

- 同一次自然回复末尾生成可选的隐藏continuity_memory片段，不增加摘要模型请求。后端剥离后才展示和保存回复。
- 至多5条笔记，每条至多240字，类别为已讨论、学生决定、待确认问题、下一步；每条必须引用已加载消息或上一版有效笔记的来源编号。
- 保存在SQLite任务body的teaching.continuity，包含revision、来源消息编号、代码哈希、最近交流原文片段。
- 不是掌握证明，也不是系统指令；不能覆盖最新计划、执行或学生验收状态。代码变化会标注记忆版本过期。
- 缺失/错误的记忆格式不导致正常回复失败；保留旧有效笔记，并更新最近交流的原文片段。整轮失败、结果过期时不提交新记忆。
- 旧历史摘要仍保留；首次接续可附最近一段旧摘要，早期原文继续可查。

## 保留的接口与机制

检查点事件与暂停/恢复、阶段确认、文件读取、消息历史读取、行号定位及版本校验、课后知识整理与审核检索、Skill预留接口、evolve接口均保留。Teacher仍没有修改代码权限。

## 观测

成功教学轮次记录context_usage、request_attempts、continuity_revision及只读工具轨迹。backend teaching_run记录整轮耗时。大小按JSON字符统计，不冒充token数；减小输入不保证消除服务商排队或模型生成延迟。此次不实现流式文字输出。
