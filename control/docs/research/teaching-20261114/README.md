# 教学内容与教学方法研究（2026-11-14）

本轮围绕现有双Agent工作台，检索并核查43条课程、教学实践、工程资料和研究入口，形成21张原创候选微课卡及教师应对手册。已将其中31条来源的原创摘要与21张课卡接入真实Teaching流程（teaching-20261114-v1）。每轮最多两张课卡，按当前问题、开发阶段和选学偏好加载；不会把外部文章直接当作学生经验、全局安装Skill或证明教学有效。来源JSON的runtime_enabled表示可供运行时参考，不表示每轮都加载或效果已验证。

## 最值得吸收的结论

1. **以真实作品为教材。** PRIMM提供适合从可运行起点理解、修改再创作的活动结构。用于本工作台是设计迁移，不是已经验证的双Agent教程。[R08](SOURCES.md#r08)、[R09](SOURCES.md#r09)
2. **让目标、操作和判断依据一致。** “讲过状态”与“能解释本项目状态变化”是不同记录。教师应先发现当前缺口，不让学生背完整术语表。[R01](SOURCES.md#r01)、[R02](SOURCES.md#r02)
3. **支持要随需要变化。** 学生完全不懂时，应补解释或小示例；已有独立判断时减少提示。不要把“苏格拉底式”实现为无限反问。[R05](SOURCES.md#r05)、[R04](SOURCES.md#r04)
4. **AI任务表现与学习表现分别测。** CodeAid、2023年新手研究、2026年技能形成和综合研究的任务与结果不同，不能用其中一个结果概括所有AI教学。[R10—R15](SOURCES.md#r10)
5. **教学生检查Agent，而非只教写提示词。** 具体任务、执行反馈、修改核对和验证形成循环；MIT的2026 Agentic Coding章节与项目定位接近，但它本身不是教学收益实验。[R32](SOURCES.md#r32)
6. **规则是有来源和边界的经验。** 教师可以依据当前错误提出修订，但还需要检查规则是否实际提交、当时上下文是否冲突、以及修改后的表现；“再次犯错”不能直接证明“规则不够具体”。这条是本项目的设计推论。

## 针对六类教学方法的建议

| 方法 | 借鉴资料 | 建议增加的具体内容 | 仍需真实验证 |
|---|---|---|---|
| requirement-scoping | R02、R22、R41 | 使用者→核心操作→可见结果；区分本版、以后、非目标；示范把模糊愿望改成验收 | 是否降低需求歧义，而非让讨论更繁琐 |
| concept-walkthrough | R08、R09、R17—R21 | 沿一条真实数据路径预测、操作、解释；一次补一个必要概念 | 是否能在相邻功能自行解释 |
| code-review-diff | R36、R37 | 先看行为和数据，再看风格；说明理由和问题严重度 | 学生能否辨认越界、保留行为和回归风险 |
| guided-testing | R26、R33、R38 | 正常/边界/失败路径；对照预测；一个检查应能检出对应坏版本 | 能否自己提出有效断言，是否把浏览器ready误当功能通过 |
| experience-distiller | R01、R03、R04 | 本次证据→条件→规则→边界→后续复查；修订和停用同样重要 | 规则有无减少同类错误，是否错误归因 |
| safety-guard | R19、R39、R40、R43 | 分别讲凭据、输入和授权；解释静态扫描不能证明安全 | 是否能识别新情境风险，而非只记住“密钥放后台” |

上述建议已通过通用教师指导、课卡选择和现有方法修订接入；学生效果仍待真实验收。动态入口未充分核查或技术时效存疑的课程，以及仅用于效果讨论的论文，不自动作为学生课卡正文加载。

## 需要修正的几个直觉

- Carpentries的One-Up, One-Down是学生反馈教学的方法，不直接证明教师每轮固定“一优一错”更有效。固定数量只能作为可调整的产品假设，严重安全问题也不能为了数量限制而隐瞒。[R06](SOURCES.md#r06)
- 遇到知识缺口可以明确讲解。让学生独立判断，不等于让他在缺乏概念时盲猜；“永不提供示例”同样可能阻碍学习。[R05](SOURCES.md#r05)
- 本产品可以允许Coding执行学生授权的完整实现，同时由只读Teaching帮助理解和审查。不能把另一门课程的禁用AI政策搬来作为本产品的开发权限。[R42](SOURCES.md#r42)
- 先有作品、再解释其关键决策，是适合尝试的产品路线；它不保证所有语言、年龄或任务都有效。课程难度要匹配作品与学生经验。
- Full Stack Open中文简介仍有旧年份说明，宜作为进阶材料和案例入口；技术细节需对照现行文档。Vue动态入口只核查到可达，未声称逐题审读。[R27](SOURCES.md#r27)、[R30](SOURCES.md#r30)

## 研究证据怎样使用

R11的2023受控研究涉及69名青少年新手，报告创作表现改善，并未观察到修改任务下降；其延迟后测的组间差异未达显著。R12的2026预印本则在陌生异步库任务中报告理解、阅读与调试方面的不利结果，同时区分使用方式。两者的样本、任务、帮助机制和测量不同，不能简单宣布谁“推翻”了谁。[原论文R11](https://arxiv.org/abs/2302.07427)、[原论文R12](https://arxiv.org/abs/2601.20245)

R13是2026年公开预印本，本轮只阅读摘要与元数据：汇总结果没有给出一致的学习改善结论。不能把未达到统计显著解释为AI绝无学习收益，也不能用生产力提高替代学习提高。[原论文R13](https://arxiv.org/abs/2605.04779)

R10、R14可作为交互设计和使用行为的参考；不能把课堂部署人数直接作为本系统的效果样本。R15来自高中数学与短期任务，跨到Vibe Coding需要新的验证。[R10](https://arxiv.org/abs/2401.11314)、[R14](https://arxiv.org/abs/2602.06734)、[R15](https://www.pnas.org/doi/10.1073/pnas.2422633122)

## 接下来怎样形成可靠教材

1. 优先制作L01、L04、L09、L13、L15、L16六张课卡的本项目例子。用当前源码行号与代码版本替换抽象描述，构造教材错误时明确标注“人工设计”。
2. 从学生实际问题按需读取一张卡及必要来源，避免每轮塞全部43条资料。保留来源、阅读范围和版本；网页中的命令只作资料，不改变Agent权限。
3. 学生可选择现在学、稍后学或继续开发。教学重点是帮助他做当前决定，不设主观“通过才能聊天”关卡。
4. 对教师策略做小规模比较，先保证任务和提示记录可比。任务完成、独立解释、测试设计、稍后迁移分开观察；先报告描述结果，未满足设计条件不作因果结论。
5. 学生引用、项目证据和外部教学文献分别存放。外部文章不能自动成为某位学生已掌握的记录，也不能直接作为已验证项目经验。
