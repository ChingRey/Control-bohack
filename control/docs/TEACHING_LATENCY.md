# 教师调用链精简（2026-11-14）

真实项目保持 project_chat、自然语言教学、离线课卡、接续记忆和两个只读工具；不改变学生确认、Coding 权限或执行预算。

## 当前链路

消息保存 → 前台任务队列 → 只读取项目文件快照 → 精简证据与材料 → 模型回复（需要证据才补查）→ 校验版本并保存 → 页面显示。后台材料整理独立运行，不能阻塞聊天。

- 教师工作线程不再构造完整 UI 快照，省去不使用的版本列表、运行状态和知识列表查询。
- 问题明确写出当前项目文件路径时，提前读取对应文件；支持 `src/main.js:250`，从指定行前10行开始最多80行，总源码仍受6500字符预算。一般问题不猜测文件；缺少内容仍能使用原来的只读工具。
- 同一共享材料的最新版本等于已确认版本时，只发送一份正文，另一位置保留 `same_as_confirmed` 及版本。不同草稿与确认版同时保留，不截断原话或删除记录。
- 输入追加工作流记录后重新校验80000字符限制，课卡使用剩余预算。请求 JSON 使用紧凑序列化；不减少课卡数量、教学深度和读取工具预算。
- 提示教师直接使用已有证据，并列查询独立材料，减少逐个读取造成的串行模型往返。最多5次请求的上限仍保留，避免硬砍复杂问题能力。
- OpenAI 自然聊天不再强制 JSON；记忆摘要、材料整理及显式结构化请求仍启用 JSON。

## 整理与一致性

聊天队列忽略 `organizer_run` 的忙碌状态；Coding/Teaching/验证之间仍串行。整理使用独立只读工作副本，结束时依旧核对完整任务签名；聊天导致上下文变化时丢弃过期整理结果，不覆盖新消息、教学记录或工作流。人工修改接口原有的整理运行保护不变。

同一任务同时至多一个整理调用。运行中再次申请整理，只登记一个待处理标记，空闲后合并为一次后续整理。前端等待教师时不再把材料整理算作回复的一部分，另行轮询后台状态。

## 验证与测量

新增测试覆盖：整理挂起时聊天仍能完成、过期整理不能覆盖聊天、重复整理合并、指定文件问题一次模型调用回答且不触发旧摘要、去重保留不同草稿、自然输出与 JSON 模式隔离。

教学 turn 保存 `request_attempts`、`request_timings`、`provider_usage` 和 `context_usage.preparation_seconds`；整理保存 `elapsed_seconds`。计时只保存次数、状态和时长，不保存请求头或密钥。既有 `teaching_run.elapsed_seconds` 继续保留。

模型回复仍整段保存显示，没有实现流式传输。未擅自更换模型或向未知模型发送关闭思考参数。自动测试使用模拟模型，不能推断真实账户提速比例；上线后可用新增计时比较相同问题的请求次数及耗时。重启后端并刷新页面才能使用新链路。
