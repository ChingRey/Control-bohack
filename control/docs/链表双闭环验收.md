# 四函数、经验库与链表验收

## 进化思想

Reflexion 用任务反馈形成反思，把反思写入情景记忆，后续尝试调用记忆调整行动。Control 借鉴其中的反馈、反思、记忆和复用。教学版在全局策略发布前加了对照试用，并保存版本、适用条件和实际使用证据。[Reflexion 论文](https://arxiv.org/abs/2303.11366)

| 函数 | 任务 | 与经验记忆的关系 |
|---|---|---|
| Decide | 依据当前检查点和前测确定要练什么 | 读取个人历史评价参考。学生当前缺口与已验证经验匹配时，引用经验并细化教学目标 |
| Teach | 把策略执行成当前学生能看到的活动 | 读取已分配的版本，记录实际步骤。同轮评价有缺口时直接插入补练 |
| Evaluate | 执行固定 Benchmark，输出五维分、缺口与证据 | 写入可比较的评价结果。评分规则由 Benchmark 版本固定 |
| Evolve | 找出重复出现的缺口，提出教法改动并判定试用结果 | 读取历史试验以归纳改法，以候选开启试用并保存状态历史，验证通过后供后续匹配 |

即时闭环为前测 → Decide → Teach → Evaluate → Teach。补练由本次答卷和实际断言触发，教学动作记录评价 ID。此时学员仍在使用原策略版本，补练属于当前教学子计划。

长期闭环为 Teach → Evaluate → Evolve → 候选 → 后续对照试用 → 策略库 → 下一位学生的 Decide 与 Teach。链表版要求至少两位不同学生的可比历史试验显示相同薄弱项，才提出候选。之后用匹配起点的后续试用与基线比较。不达标准保留拒绝记录。通过后，Teach 在匹配条件下默认采用，Decide 会在前测也发现对应缺口时引用验证经验。

## 第一阶段验收

考核版本 `linked-list-delete-rubric-v1`。提交 JSON 断言，每条包含原链表 `values`、删除目标 `target`、预期剩余序列 `expected`。服务器创建真实节点并执行删除，也用有缺陷的固定实现检查学生的用例能否发现实际问题。考核覆盖空链、单节点、删头、删尾、未找到、重复值。迁移场景从删除第一个匹配改为删除最后一个匹配。判断重复值覆盖时，必须构造一个能区分删第一个和删最后一个的用例。

五维权重分别是知识理解 15%、工程判断 25%、AI 协作指导 20%、验证与纠错 25%、独立迁移 15%。概念和协作判断使用结构化作答，验证与迁移使用实际断言及缺陷识别。每一维可以展开看评分理由和证据 ID。练习有提示上限；后测和迁移阶段隐藏教法和对照记录。用同一输入可重新计算分数。独立掌握还要满足验证等级、行为检查和迁移门槛。

演示中 v1 基线只有普通内节点断言时，Evaluate 列出缺少的边界，Teach 即时插入补练。第二位基线学生也暴露缺口后，Evolve 把边界清单及「输入 → 预期 → 实际」移到引导练习，形成 v2。两位后续学生实际试用，与两条基线配对，之后用下一位学生验证 Decide 引用及 Teach 执行。策略与人群记录按 Benchmark 版本和真人/模拟来源区分。

## 运行

在项目目录运行。

```powershell
python -X utf8 scripts/demo_linked_list_evolution.py --out linked-list-demo-run
$env:CONTROL_WORKBENCH_DATA = (Resolve-Path linked-list-demo-run).Path
$env:CONTROL_ALLOW_SIMULATION = '1'
python -X utf8 backend.py --port 8783
```

打开 http://127.0.0.1:8783/?evolution=simulation 。在「考核案例」选「单链表删除」，「看跨用户进化」可查看 v1/v2。切到「单次教学试验」可手工提交断言。答卷由模拟脚本产生，节点操作、评分和数据库判定均实际运行。真人学习效果需要另行试教。

普通待办案例继续可选。两种案例分别从 v1 起算，保留已有待办策略试验。
