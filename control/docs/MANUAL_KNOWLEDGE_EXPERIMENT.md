# 人工项目经验实验

重启后端并刷新页面后，右侧 Teaching 区域顶部显示“项目经验实验（人工录入）”。无需 Teaching 模型；Coding 仍需配置真实 OpenCode 模型。

1. 填写标题与经验正文，保存为待审核条目。
2. 点击该条目的“允许检索”。批准只授权检索，不表示验证通过。
3. 用“预览检索”输入准备发送给 Coding 的需求，检查相关经验能否命中。
4. 向 Coding 发送需求；调用完成后，面板显示最近成功调用加载的条目 ID 和版本。
5. 关闭面板的知识开关，可对照下一轮不提供知识的情况。为避免聊天记忆污染，严谨对照需使用独立任务和相同代码起点。

检索只在当前任务中进行，最多提供3条相关记录。切换开关不清除已有对话，因此模型可能记得前一轮已收到的经验。加载记录只证明内容随请求提交；是否采用、采用是否正确和是否提升效果需结合回复、代码和行为检查判断。模型失败的调用不会标成成功加载。

新增 API：

| 路由 | 请求 | 效果 |
|---|---|---|
| `POST /api/tasks/:id/knowledge/manual` | `title`, `content`, `confirmed:true` | 记录人工原文，生成待审核知识 |
| `POST /api/tasks/:id/knowledge/settings` | `enabled:boolean` | 控制后续 Coding 调用的知识注入；不影响搜索预览 |

人工条目使用 `source_turn=-1`、`origin=manual_experiment`、`verified=false`，引用保存的人工输入消息。不会伪造成 Teaching 轮次或已验证的事故经验。批准、拒绝和停用沿用知识审核接口；停用的人工条目可再次批准。当前为本机实验工具，没有审核身份认证。
