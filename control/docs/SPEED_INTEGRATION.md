# 加速与过程显示适配（2026-11-15）

来源：ChingRey/Control-bohack 的 836fbbbbbd437d636afc9162c213d6a7005c70aa（加速，添加过程显示），包含其父版本 af623f4 的回复确认/执行分离。通过共同基线 8febcc7 三方合并，保留当前共享经验库、证据量表、同ID修订/停用/回退和矩阵前端。没有整体替换成 main@7a2f30f 的链表模拟实验及旧实验面板。

## 实际行为

- Coding启动时关闭模型目录拉取和自动更新，将项目内携带的ripgrep放入隔离搜索缓存，减少首次搜索下载/失败等待。凭据与用户配置仍隔离，执行上限900秒不变。
- Coding提示增加批量编辑建议：同文件独立修改尽量合并，独立工具操作尽量同轮；最终仍核对落盘。建议不能保证模型每次照做或固定减少多少轮。
- Coding子进程同时排空两条输出管道，发布生成轮次、工具完成数和执行阶段；不向进度条发送原始工具参数、推理或密钥。后台按当前job ID合并进度，不覆盖其他运行结果。
- “确认这条回复”仅保存认可；有已确认的待执行计划时另显示“执行当前阶段”。计划批准、阶段验收与聊天认可分开。Coding讨论完成也触发异步Teaching，manual模式除外。
- 真实项目Teaching改为本地重点源码选择，源码预算3600字符，保留真实完整行和行号；单文件最多1800字符。按学生指定位置、标识符及当前有效diff筛选，缺少证据须说明，不能编造省略源码。本轮不再模型读工具往返。
- Teaching项目聊天最多一次请求，流式返回，GLM思考预算1024、reasoning_effort=low、可见输出上限2600；背景评价/反思使用自己的预算，保持原证据校验与入库规则。其他提供商继续原适配；这些GLM选项不发给不匹配的模型。
- 保留材料准备、经验版本、请求响应头、首段推理信号、首字和完成耗时。只发布推理存在的状态，不发布推理内容；流式文本经过原脱敏与接续标记过滤。

## 验证

`scripts/verify_speed_integration.py` 在临时SQLite与真实Chromium验证确认不执行、显式执行、实时Coding进度、完成后Teaching流式交接、一次模型请求和经验版本轨迹；模型及Coding结果为夹具，不能据此声称真实Coding变快。`scripts/verify_shared_experience.py` 验证经验矩阵、高亮、折叠、跨项目引用与撤销未被覆盖。

`scripts/demo_speed_live.py` 使用主机真实配置的 GLM-5.3-Flash，仅针对内存中的模拟计分项目提问，不保存学生项目或经验。2026-11-15单次样本：材料准备0.006秒、响应头1.660秒、首字1.974秒、请求完成7.881秒、整体7.890秒，1次请求。记录：data/demos/speed-live-20261115-030938/result.json。没有同条件旧版对照，不计算加速比例，不保证所有任务都在该时间内完成；真实Coding耗时和长项目讲解质量仍需后续观察。
